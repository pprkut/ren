# 0011 — Web pages in tabs (M7)

**Status:** done (2026-10-10), for review; measured on the desktop on
2026-10-10, except for scrolling heise after its consent banner.

## Context

S4 (`0005`) decided on Servo in a helper process with frames read back
from the GPU, and left the tabs as spike code: the in-process and wgpu
variants, a socket path, JSON lines on stdin, frames through the socket,
a helper that could outlive ren, and Servo pinned to 0.5 so that it
shared stylo with Blitz. The plan's M7 asked for the tab bar, "Open
page", the on-demand lifecycle, the per-feed "open full page instead of
article" setting, and the points of the S4 review and of "Scrolling
heavy pages".

## Pivot: Servo is a program of its own

The S4 review wanted Servo kept current instead of pinned to Blitz's
stylo, accepting two stylo versions. That can't be done in one build:
stylo declares `links = "servo_style_crate"`, and Cargo allows only one
package per `links` value in a dependency graph. Blitz 0.3.0-beta.2
needs stylo 0.20, Servo 0.6 needs 0.21 and Servo 0.7 needs 0.22 (Blitz's
unreleased main branch is on 0.22). As long as both are built into ren,
every Servo release waits for a Blitz release on the same stylo.

Options weighed, and the user's choice:

| option | runtime | build |
|---|---|---|
| **Servo in a program of its own, monthly releases** (chosen) | the same processes as S4; the window's binary without Servo's code | two workspaces, two `cargo build`s; Servo upgrades independent of Blitz |
| the same, on Servo's LTS line (0.6, security fixes for nine months, a new LTS every six) | as above | upgrades on a schedule |
| stay on Servo 0.5 with a shared stylo | as S4 | no security fixes until Blitz and Servo meet on a stylo again |

So `crates/ren-servo` is a workspace of its own (excluded from ren's,
with its own `Cargo.lock`) that builds the helper `ren-servo` on Servo
**0.7.0**; ren starts it from next to its own binary, from
`../libexec/ren/`, or from `$REN_SERVO`. What both sides share is the
protocol crate `ren-tabs`, a member of ren's workspace and a path
dependency of the helper's. `just build` builds both; `just
check-servo` and CI's Servo job lint and test the helper's workspace;
the `servo` feature of ren is now only the window's side (no Servo),
on by default and in `just check-light`. Servo 0.7 is built without its
`multiprocess` feature (the helper is the process boundary) and without
its opt-in web features (WebGL, WebGPU, WebXR). ren-store's rusqlite is
no longer tied to Servo's.

## What was built

### The protocol (`ren-tabs`)

- **One inherited socket pair** instead of a socket path (and its
  fallback to the temporary directory) plus stdin: ren creates a Unix
  socket pair and passes one end as the helper's standard input; stdout
  and stderr stay free for Servo's output. Messages both ways are a
  little-endian u32 length and JSON, at most 1 MiB.
- **Frames through shared memory:** ren makes a memfd for the page's
  size (rounded up to 128 pixels, so resizing the window doesn't make a
  buffer per pixel; a new one when it's too small or four times too
  large), **seals its size** (`F_SEAL_SHRINK | F_SEAL_GROW |
  F_SEAL_SEAL`: the helper runs web content and could otherwise truncate
  it and crash ren with SIGBUS) and sends it with `SCM_RIGHTS`. The
  helper writes RGBA frames, top row first, and announces them with the
  buffer's id and size; ren checks they fit the buffer it made. ren's
  receiver keeps no file descriptors the helper might send.
- **Frame pacing:** the helper writes the next frame only after ren
  answered `FrameTaken`, so a frame is never written while ren reads it,
  and frames ren couldn't show aren't painted or read back at all: the
  newest one is painted when ren is ready.
- Tests: messages split anywhere, oversized and broken ones, file
  descriptors passed and dropped, the seals, buffers that don't fit.

### The helper (`ren-servo`)

- **Dies with ren:** `PR_SET_PDEATHSIG` (SIGKILL), after checking ren is
  still its parent (ren may have ended before). A closed socket also
  ends it, the normal way.
- **Bounded shutdown:** Servo's shutdown saves cookies and site data,
  but can hang once ren is gone (S4: an orphaned helper ran on for 10
  minutes); after 3 s the helper kills itself.
- **Asynchronous readback:** after Servo painted, `glReadPixels` goes
  into a pixel buffer object with a fence; the helper's loop polls the
  fence every millisecond while one is pending and goes on handling
  Servo's messages and ren's commands, instead of waiting in
  `glReadPixels` for the GPU (4–22 ms per frame on heise in S4, up to
  160 ms). The rows are flipped while copying from the mapped buffer
  into ren's.
- **Navigation only to web pages:** Servo's `request_navigation` allows
  `http`, `https` and what pages make themselves (`about:`, `data:`,
  `blob:`; iframes need them); `mailto:` goes to ren, which hands it to
  the desktop; `file:` and other schemes are refused. Tabs only open
  `http`/`https` URLs.
- **Popups:** `window.open` and links to new windows open a tab next to
  their opener, which is shown; `window.close()` closes the tab. At
  most 50 tabs.
- **History:** back, forward, reload; the URL, title, loading state and
  whether the tab can go back or forward go to ren.
- **A Servo profile** (`Opts::config_dir`): cookies, local storage, the
  HSTS list and the auth cache are kept in the directory ren passes;
  without one, storage is temporary.
- **Smooth wheel scrolling:** wheel steps of 40 physical pixels or more
  are spread over ticks of 16 ms, each scrolling 35 % of what is left
  (about 100 ms); shorter steps (touchpads) go at once, taking along
  what was left. Pure logic, tested.
- **glibc's mmap threshold** is fixed at 1 MiB, as in ren (`0010`),
  unless `REN_SERVO_DYNAMIC_MMAP_THRESHOLD` is set, so `just
  measure-tabs` can compare the two.
- A crashing page ends its tab, not the helper (`hard_fail` off).
- Debug info only for the helper's own code: Servo's needs about 18 GB.

### The window

- **Lifecycle:** the helper starts with the first tab and ends with the
  last. When the last tab closes, ren shuts the socket down and a thread
  waits for the helper (killing it after 4 s), so the UI thread doesn't
  wait (S4 waited up to 3 s on it). When ren quits with tabs open, it
  closes them and waits for the helpers, so their site data is saved
  before ren's exit kills them (the death signal).
- **Frames:** copied from the shared buffer into one of two pixel
  buffers on the UI thread, then answered. When the last tab closes the
  image is dropped and the heap trimmed; the pixel buffers are above the
  1 MiB mmap threshold, so they go back to the system anyway.
- **The tab list** is a view model of its own (`tabs/list.rs`, tested):
  closing the tab shown shows its right neighbour, else its left one,
  else the article; tabs that pages open go next to their opener;
  titles, URLs, loading and history from the helper.
- **A navigation bar** above the page: back, forward, reload, the
  address, and Open in Browser. Go → Back and Forward (Alt+Left/Right),
  the mouse's back and forward buttons, File → Close Tab (Ctrl+W).
  Icons from the theme (`go-previous`, `go-next`, `view-refresh`,
  `internet-web-browser`), with Lucide fallbacks.
- **Full pages per feed:** the feed's context menu has "Show Full Pages
  Instead of Articles" (the store's per-feed setting from M2). Selecting
  an article of such a feed marks it read, shows it in the Article tab
  and opens its page in a tab; the next such article loads in the same
  tab, so reading through a feed doesn't pile up tabs.
- **Site data:** kept in `$XDG_DATA_HOME/ren/servo` (made readable only
  by the user), unless `pages.keep-site-data` is off. Settings → Clear
  Web Site Data closes the tabs, waits for the helper and removes the
  directory.
- Keys are mapped to the protocol's keys in the window (F1–F12 added),
  so the helper doesn't need Slint; control characters for keys without
  a mapping (Caps Lock, …) are no longer typed into pages.
- The spike's `--tabs in-process`, `--tabs wgpu` and `servo-wgpu` are
  gone.

## Checked in the container

Under Xvfb with Mesa's llvmpipe, debug builds, local test pages: pages
render and scroll; `window.open` opens a tab next to its opener; links
in pages, back and forward work; a `file:` navigation is refused and a
`mailto:` one goes to `xdg-open`; a cookie set in one helper is there
in the next and saved to the profile, which is created with mode 0700;
killing ren (SIGKILL) ends the helper; quitting with tabs open saves the
site data and ends the helper; a full-page feed loads the next article
in the same tab; Close Tab works. `just measure-tabs` runs through (with
the debug binaries); its numbers there say nothing about the desktop:

Against S4's helper variant (the same dump pages):

- **Less memory everywhere:** 48.0 MiB before the first tab (S4: 56.9;
  ren no longer carries Servo's code), 248.4 with one tab (288.5), 311.9
  with three (418.0). The helper itself is 30 MiB smaller with one tab
  and 90 MiB with three: Servo 0.7 without WebGL, WebGPU and its
  multiprocess support, and the fixed mmap threshold; the run doesn't
  separate the two.
- **The window costs 18.4 MiB while a tab is open** (S4: 19.5): the
  shared frame buffer (5.9 MiB, counted in both processes) and the two
  pixel buffers it is copied into.
- **After closing, the window kept 6 MiB** of anonymous memory (7.1 →
  13.2, S4: 6.3), the same after a second round. It was one frame:
  Slint's renderer keeps the image of an `Image` element until it draws
  it again, and the hidden page pane isn't drawn again. Fixed in
  3d999fd (the element only exists while a page is shown); in the
  container the window is now 0.2 MiB above its start after closing
  (1.7 before, with a smaller page). Not measured on the desktop yet.
- **Starting and stopping:** 0.9 ms to start the helper (S4: 6.1, which
  waited for the socket to connect), 1.2 ms to stop (S4: 30.2; the UI
  thread no longer waits for the helper).
- **Frames:** 3.9 ms on average from a painted frame to the window, at
  most 8.6 (S4: 6.9 / 20.8), now including the time the GPU takes for
  the frame, during which the helper goes on working; 133 frames while
  scrolling for 3 s (S4: 127).
- **The mmap threshold:** with three tabs, the fixed threshold used 13
  MiB less on the dump's pages and 59 less on Ars Technica, 19 more on
  heise (53 MiB less over the three); the longest frame was shorter with
  it in two of the three. Pages differ from run to run (ads), so single
  differences of 20 MiB are within the noise, but nothing speaks for
  glibc's dynamic threshold. **The helper keeps the fixed one.**
- **Heavy pages:** Ars Technica scrolls with 162 frames in 3 s (54 per
  second, S4's plain pages 127); the frames take 11 ms on average to
  reach the window and up to 87 ms, which is mostly the GPU's work on
  the page and no longer blocks the helper. heise gave only 5 frames:
  its consent banner covers the page and keeps it from scrolling (S4
  measured after accepting it). Since M7 the consent is kept in the
  profile, so accepting it once in ren and measuring again shows
  whether heise scrolls as smoothly.
- **Heavy pages are big:** a heise tab costs the helper about 250 MiB
  (907 MiB with three), an Ars Technica tab about 160 MiB. Content
  blocking would cut part of it; see "Open".

## Open

- **Content blocking** (optional in the plan) isn't done: filtering ad
  and tracker requests through Servo's `load_web_resource` with a
  filter list (e.g. the `adblock` crate). Decide after the measurements
  of heavy pages.
- **Keys with modifiers** go to the page and to the window's shortcuts
  (Ctrl+F in a page also focuses ren's search).
- Not handled from Servo's embedder controls: `<select>` drop-downs,
  context menus, file pickers, colour pickers, IME, and `alert`/
  `confirm`/`prompt` dialogs (dismissed). `<select>` is the one pages
  need most.
- **Popups** don't need a user gesture: a page can open tabs by itself,
  up to 50.
- Top-level `data:` navigations are allowed (Servo's hook doesn't tell
  the main frame from iframes).
- **The article view probably keeps its last frame too** while a page is
  shown, for the same reason as the page (Slint keeps the image of an
  element it doesn't draw): about one frame of the article's size.
  Check and fix like the page (M8 or M10).
- **Content blocking** would matter for memory as well: 160–250 MiB per
  tab of a heavy news page.
- Clear Web Site Data waits for the helper on the UI thread (rarely
  more than a few milliseconds, at most 4 s).
- WebGL, WebGPU and WebXR are off; turn them on if pages need them.
- Servo's monthly releases change its API; each upgrade is a commit of
  its own in the helper's workspace. CI's weekly run builds the helper.
- Packaging the helper (`libexec/ren/ren-servo`) is M11's.
- The page's frame is copied once in the window (from the shared buffer
  into a Slint image); Slint has no image type that borrows memory.
